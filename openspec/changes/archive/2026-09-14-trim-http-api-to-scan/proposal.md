## Why

The HTTP API listener serves three routes, but only `POST /v1/scan` does the job the
listener exists for. `GET /v1/info` and `GET /openapi.json` describe the deployment
rather than inspect a message, and they carry cost out of proportion to their use: a
permissive `Access-Control-Allow-Origin: *` layer on the public listener, 85 lines of
runtime spec-generation machinery, a `tower-http` dependency, and an unauthenticated
nginx demo container in the compose stack.

The generated specification is still worth keeping. It is generated from the handlers,
so it cannot drift. This change keeps the generation and drops the route: the document
becomes a checked-in artefact under `docs/`, verified by a test, instead of a public
endpoint.

## What Changes

- **BREAKING** `GET /v1/info` is removed. The listener answers 404.
- **BREAKING** `GET /openapi.json` is removed. The listener answers 404.
- **BREAKING** The HTTP API no longer sends CORS headers. A browser on another origin
  can no longer call `POST /v1/scan` directly.
- `POST /v1/scan` is unchanged: same request body handling, same response shape, same
  status codes, same limits.
- The OpenAPI document moves from a served route to a checked-in `docs/openapi.json`,
  generated by the same `utoipa` annotations and held in step by a test that fails when
  the generated document and the checked-in file differ.
- The `demo` service and `docker/demo/` leave the compose stack. They exist only to
  render `/openapi.json` and to call `/v1/info`.
- The admin listener, the reverse proxy, and the forward-proxy configuration stub are
  untouched.

Out of scope: the reverse proxy `:8082`, the forward proxy `:8084`, and the admin
listener `:9090` keep every route they have today.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `http-api`: the listener serves one route, not three. The `GET /v1/info` and
  `GET /openapi.json` requirements are removed. A new requirement states that the
  OpenAPI document is a generated, checked-in file rather than a served route.
- `security`: the requirement that the scanner configuration is not exposed keeps its
  rule but loses its `/v1/info` scenario, because the route no longer exists. A new
  scenario states that the API listener sends no CORS header.

## Impact

Code:

- `crates/voidwall/src/http_api.rs` — remove the two routes, `info_handler`,
  `openapi_handler`, `InfoResponse`, `kind_labels`, `language_labels`, the `CorsLayer`,
  and the `ApiState.openapi_spec` field. Keep `ApiDoc` and `build_openapi_spec` for the
  file-generation path.
- `crates/voidwall/Cargo.toml` — drop `tower-http`; it has no other user in the
  workspace. Keep `utoipa`.
- `crates/voidwall/tests/http_api_integration.rs` — delete the two route tests, add 404
  proofs for the removed paths, add the spec-freshness check.

Docs and tooling:

- `docs/openapi.json` — new, checked in.
- `docs/api-docs.md` — rewritten. The Swagger UI sections and the CORS paragraph go; the
  compose service table loses the demo row.
- `docker/docker-compose.yml`, `docker/ctl`, `docker/demo/` — the demo service, its port
  `8088`, and its files are removed.
- `docs/backlog.md` — the "Demo page smoke test" gap is dropped as stale.

Not affected: the metric contract. `voidwall_requests_total` already carries a fixed
`route="global"` and a hard-coded `POST` method for this listener, which becomes exactly
true once the two `GET` routes are gone.
